Retro Weather v1.1 Test16 — Optional small MP4 replay (2026-11-15)

Close Retro Weather and install over Test15. Choose Help > Run Full Diagnostics / Benchmark. A new options dialog offers recording OFF by default. The existing 305-second timed benchmark runs first, unchanged. If recording is enabled, a separate 108-second replay then shows all nine weather scenes and all seven pages in each scene. Recording/encoder initialization cannot affect the earlier timing results. Total with recording is about seven minutes plus encoder setup/finalization.

Options: 720p or lighter 480p, maximum 10 FPS, aspect ratio preserved with even video dimensions. No upscaling of normal-sized sources. File-size limits: 10, 25 (default), or 50 MB (binary MB units). H.264 target bitrate is reduced for the smaller limit. Default 720p + generated audio estimates roughly 13 MB for the full replay; actual codec output varies. 480p is usually smaller. A bounded two-frame queue drops captures instead of accumulating raw frames. No raw recording files are written to disk. Encoders run on a below-normal-priority worker; Windows may use hardware or software encoding. Encoder internal buffers are managed by Windows.

MP4 uses Windows Media Foundation H.264/AAC encoding; Windows 7+ media components/encoders are required. These DLLs are dynamically loaded only for recording, with no new Media Foundation DLL imports. On XP, the recording checkbox is disabled and the normal text benchmark remains available. Missing/unsupported encoders on newer Windows are reported without discarding the text benchmark. Windows N editions may lack media components.

Capture includes only the app's offscreen simulated weather picture: no desktop, progress dialog, microphone or system-audio capture. Optional AAC audio is generated from the bundled sounds, resampled to 44.1 kHz mono, at the temporary benchmark volume. It is an intended soundtrack, not evidence that waveOut/the physical speakers worked; keep listening during the timed run. Replay audio boundaries follow scene transitions; this is not a recording of the actual driver crossfade.

The MP4 is streamed into Documents\Retro Weather\Diagnostics. The final combined text report uses the same timestamped base name when available. The report includes recording resolution/bitrate, written/dropped/missed frame counts, captured scene/page masks, file size, duration, errors, and separate recording-only process CPU/peak working set. Recording statistics are separate from benchmark performance. Post-run memory may retain Windows encoder/allocator caches.

Size monitoring stops recording early near the selected limit with room for MP4 metadata. Finalized output above the limit is removed; failure to remove an owned incomplete/oversized file is explicitly reported. Existing files are never intentionally replaced: a new unique name is reserved first. Cancellation during timing exports partial text without recording. Cancellation during replay stops/finalizes a partial MP4 and retains the completed timed results. Resize/minimize during replay stops capture; original settings/live weather/audio are restored before export. Encoder finalization can take a few seconds. Output failures keep the combined report available for Quick Export retry in the current process.

TEST: run once with recording off to compare normal behavior; then enable recording (720p, 25 MB, audio) and run again. Upload the paired .txt and .mp4. Check video is upright, colors/text legible, scenes/page changes present, audio intended soundtrack present, file size within the selected cap, and live settings restored afterward. First native Windows encoding run remains pending. Use 480p if capture overhead/drop count is high. No overnight testing needed.

Reference implementation guidance: Microsoft Learn, Using the Sink Writer / Sink Writer Video Encoding Tutorial, H.264 Video Encoder and AAC Encoder. No external encoder executable or codec download is bundled.

Retro Weather v1.1 Test15 — Full Diagnostics / Benchmark (2026-11-14)

START: Help > Run Full Diagnostics / Benchmark, or About / Diagnostics > Full Benchmark. Wait for any live weather/location operation to finish first. Use your normal display resolution. Keep the player visible and leave the benchmark running while listening to its expected audio.

One run takes approximately 5 minutes 5 seconds:
- Basic Blue idle baseline: 15 sec, including 5 sec settling.
- Clear day, clear night, partly cloudy, overcast, drizzle, rain, thunderstorm, snow and fog: 30 sec each, including 5 sec settling and 25 sec measurement. All seven pages are shown in each weather stage. Each measured scene window exceeds the bundled sound's 17 sec loop length; listen to confirm actual continuity.
- Playback control checks: 20 sec, exercising pause, resume, Audio Off, Audio On and post-transition state.

Progress and current expected sound appear in a small dialog. Normal CPU budget, frame cap and adaptive graphics remain active. Audio is temporarily enabled at your current volume (25% if it was zero) for listening, then the original enabled/volume/paused state is restored. The live weather dataset/time zone, background, page and page timing state are restored at completion/cancellation. Settings persistence and background weather/location requests are suspended during the run. Minimize/restore, screensaver activation and alternative resolutions are not automated; repeat at other resolutions if desired.

One timestamped UTF-16 text file named RetroWeather_Benchmark_*.txt is saved automatically in Documents\Retro Weather\Diagnostics after completion, cancellation or an interrupted run. The success dialog shows its path. It contains all completed/partial stage entries, initial/post-run snapshots, actual resolution/quality, CPU (overall and single-core equivalent), FPS, warm composition average/p95/max, transient/cache spikes, drawing costs, sampled memory/handle peaks and playback API checks. Mixed quality/geometry is flagged. Audio audibility and visual smoothness/lighting/trails are explicitly manual checks, not automatic PASS claims.

Cancel and Export stops promptly and exports partial results. Original settings/live data are restored first. If automatic export fails, the latest combined report remains in About / Diagnostics and Quick Export can retry while the process stays open. Closing after a failed export loses that unsaved in-memory report. A system shutdown or crash can prevent final export.

Retro Weather v1.1 Test14 — Audio fade handoff fix (2026-11-14)

User reported rain sounding briefly then going silent. A new shared-mixer driver simulation reproduced a crossfade defect: applying zero volume to the outgoing waveOut handle can also mute the incoming loop when handles share mixer volume. The old tests assumed independent per-handle volume.

Fix: apply outgoing gain first, incoming gain last. At fade completion, close the outgoing stream then reapply the current stream gain. Independent-volume drivers retain the same crossfade gain values; shared-mixer drivers no longer finish at outgoing zero. Actual crossfade quality still depends on driver volume behavior. No new threads, sound buffers, decoding or per-frame volume calls. The existing 100ms fade timer remains.
Diagnostics now include Audio transition and Last volume API result (0 means the most recent waveOutSetVolume call succeeded). These report API state, not proof of audible output.
Rendering, rain distribution/direct-DIB drawing, shift bounds, scenery, frame cap, CPU budget and preview data are unchanged from Test13.

Windows 11 test: close Retro Weather and install over Test13. Enable Audio. Switch TEST-NIGHT -> TEST-RAIN; sound should continue after the 1.6-second fade. Try TEST-DRIZZLE (same rain loop), TEST-STORM -> TEST-RAIN, Audio Off/On and pause/resume. Let rain run for at least 20 seconds to cross its 17-second loop boundary. Send a Quick Export if sound still stops. Recheck Basic themes remain silent. No overnight test needed. Physical XP validation remains deferred.
